# Twenty-two additional reconstructed original bodies

This batch adds 22 new original-address implementations to the executable's recompiled core, with direct caller connections and executed regression coverage. The compiled-source ledger advances from 419 to 441 of 615. This metric does not mean complete native gameplay integration or retail ABI equivalence.

The nine exception functions reconstruct the owned base message, reference-counted string payload, allocator byte, copy constructors, cleanup variants, and the two string error throw paths. On x86 the source object is 28 bytes with its string at offset 12. The original string methods now call the reconstructed throw paths directly. Native throwing adapters retain host `std::length_error` and `std::out_of_range` catch compatibility while owning the reconstructed payload. Native C++ unwinding replaces the original FS/EBP exception registration machinery; these are source reconstructions rather than binary SEH landing-pad replacements. The base message at 00482574 is confirmed as zero-initialized PE storage, not a guessed string.

Startup reconstruction includes the full backslash/quote argv parser, contiguous argv initialization, filtering/copying the process environment, reverse onexit cleanup, both forward initializer ranges, strcat, virtual-base PMD adjustment, the wrapped-size calloc selection/retry loop, descriptor-block allocation, inherited descriptor initialization, close, and seek. The original two-pass DBCS sizing quirk is preserved: inside a quoted program name, the count-only pass increments for a lead byte without advancing past its trail byte. Native argv pointer storage uses host pointer width; guest handles and PMD addresses remain explicit 32-bit values.

Required process, allocation, descriptor and guest-memory services have no default successful implementations. Actual OS side effects still require the host provider. Regression fixtures supply controlled dependencies and validate call order, failures, storage changes and allocation cleanup; they are not substitutes for a native gameplay host. `connect_close` connects the existing `0042FB62` fclose implementation through `BufferedIoLink` to the new original close routine, retaining the recovered flush/commit implementations. Tests exercise the full fclose-to-descriptor chain.

The original help loader uses 25 counts, 24 parsed groups, 30-region strides, the default exit rectangle, the popup-specific rectangle, `END`, and the five-field sentinel. A real asset-resolver overload reads `loaddata/helpinfo.txt` from the supplied installed/disc roots. `GameRoot::begin_original_help` calls the recovered entry function using the live outer state. The service order is surface copy, activation reset, help intro voice, hover reset, then original context selection and progress override. Rendering/audio operations require real services; the full hover/update function 00401700 remains unreviewed.

Instruction listings for all 22 addresses and the exception global-data evidence are preserved in `analysis/retail_instruction_evidence`. `tools/build_retail_startup_vectors.py` regenerates 3,272 original x86 parser/strcat/PMD vectors and 272 original help-entry state vectors. The help emulation controls DirectDraw Blt and PlayHelpVoice dependencies; it compares the original entry routine's context/global writes, not graphics or audio output. The parser tests cover quotes, tabs, backslashes, unmatched quotes, empty arguments and the DBCS count pass. Cleanup tests cover owned/borrowed payloads, shared strings, saturated reference counts, allocation failures, inherited handles, shared stdout/stderr handles, close/seek errors, process callback order, and new-handler retries.

The full Clang 19 C++26 build and 126 CTest tests pass. Exception and startup tests also pass native address/undefined-behavior sanitizers; leak detection is disabled for the restricted `/proc` environment, while test fixtures track and free their live allocations. Sixteen Python tool tests pass. Platform CI includes all three new targets.

Safe host input validation rejects malformed help groups and inherited descriptor blocks, invalid guest reads, truncated multibyte input, and count/fill disagreement that would overrun argv pointer storage. Descriptor-startup allocation failure raises `std::bad_alloc` in the portable interface instead of terminating the host through the original fatal error 27. These distinctions are outside claimed valid-input source parity. Full game integration, OS behavior, original x86 ABI and universal retail verification remain incomplete; no function is promoted to `behavior_verified`.
